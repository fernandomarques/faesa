## Corte de Hastes - Dada uma haste de _n_ polegadas de comprimento e uma tabela de preços $p_i$ para i = 1,2,3...,n, determine a receita máxima $r_n$ que se pode obter cortando a haste e vendendo os pedaços - Preços: ${ 1, 5, 8, 9, 10, 17, 17, 20, 24, 30}$ - Quais as soluções para hastes de tamanho: { 5, 7, 10 e 15}
A ideia central: **fixar o primeiro corte e resolver o resto otimamente.** Para uma haste de tamanho $n$, tentamos cada possível primeiro pedaço: n = 4 - ├── corte 1 → preço[1] + melhor(3) - ├── corte 2 → preço[2] + melhor(2) - ├── corte 3 → preço[3] + melhor(1) - └── corte 4 → preço[4] + melhor(0) - Fixamos o primeiro, ele **não será cortado mais** - O restante é resolvido **recursivamente** - Escolhemos a opção de **maior receita total** > "Qual o melhor primeiro corte?" e o resto cuida de si mesmo.

## Corte de Hastes - O tempo de execução é de T(n) $ = 1 + \sum_{i=0}^{n-1}T(i) $ - $ T(n) = O(2^n) $ - Como melhorar isso?
Considere calcular `cut-rod(p, 4)` — a árvore de chamadas explode: cut-rod(4) - ├── cut-rod(3) - │ ├── cut-rod(2) - │ │ ├── cut-rod(1) - │ │ └── cut-rod(0) - │ ├── cut-rod(1) ← repetido! - │ └── cut-rod(0) ← repetido! - ├── cut-rod(2) ← repetido! - │ ├── cut-rod(1) ← repetido! - │ └── cut-rod(0) ← repetido! - ├── cut-rod(1) ← repetido! - └── cut-rod(0) ← repetido!
## Programação Dinâmica | Divisão e Conquista | Programação Dinâmica | |---|---| | Subproblemas **independentes** | Subproblemas **se sobrepõem** | | Resolve cada um do zero | **Lembra** o que já resolveu | | Combina as soluções | Constrói de baixo para cima | - Aplicada a problemas de **otimização**: encontrar o valor máximo ou mínimo dentre muitas soluções possíveis - Exemplo clássico: [Fibonacci com memoização](fibonacci.py)
## Programação Dinâmica - O desenvolvimento segue quatro etapas: 1. Caracterizar a estrutura de uma solução ótima 1. Definir recursivamente o valor de uma solução ótima 1. Calcular o valor de uma solução ótima, normalmente de baixo para cima 1. Construir uma solução ótima com as informações calculadas

As 4 etapas da PD aplicadas ao Corte de Hastes

1. Estrutura da solução ótima: A receita máxima $r_n$ para uma haste de tamanho $ n $ é: $ r_n = \max_{1 \leq i \leq n} (p_i + r_{n-i}) $ Cortamos um pedaço de tamanho $i$ e resolvemos otimamente o restante.
Subestrutura ótima: a solução do todo contém soluções ótimas das partes.

2. Definição recursiva do valor ótimo

$$r_0 = 0$$ $$r_n = \max_{1 \leq i \leq n}(p_i + r_{n-i})$$

3. Calcular de baixo para cima

Preenchemos `r[0], r[1], ..., r[n]` em ordem. Cada `r[j]` só depende de valores menores, já calculados.

4. Construir a solução

Guardamos também `s[j]` = tamanho do primeiro corte ótimo para haste `j`. Para reconstruir: imprimimos `s[n]`, depois `s[n - s[n]]`, e assim por diante.
## Solução 1: Memoização (top-down) Mesma lógica recursiva, mas **guardamos** cada resultado calculado: ```python def cut_rod_memo(p, n, memo={}): if n in memo: return memo[n] # já calculei, só retorno if n == 0: return 0 q = float('-inf') for i in range(1, n + 1): q = max(q, p[i] + cut_rod_memo(p, n - i, memo)) memo[n] = q # guardo antes de retornar return q ```
- Cada subproblema é resolvido **exatamente uma vez** - Tempo: $O(n^2)$, dois loops aninhados implícitos - Espaço: $O(n)$ para a tabela memo > Trocar $O(2^n)$ por $O(n^2)$ apenas guardando resultados.
## Solução 2: Bottom-up (iterativa) Em vez de descer recursivamente, **subimos** do menor subproblema: ```python def cut_rod_bottom_up(p, n): r = [0] * (n + 1) # r[i] = receita máxima para haste de tamanho i for j in range(1, n + 1): q = float('-inf') for i in range(1, j + 1): q = max(q, p[i] + r[j - i]) # usa resultados já calculados r[j] = q return r[n] ```
Executando para `p = [0,1,5,8,9,10,17,17,20,24,30]`: | j | r[j] | Melhor corte | |---|------|-------------| | 1 | 1 | 1 | | 2 | 5 | 2 | | 3 | 8 | 3 | | 4 | 10 | 2+2 | | 5 | 13 | 2+3 | | 10| 30 | 10 |
**O problema:** $2^{n-1}$ combinações possíveis: força bruta não escala. **A estratégia:** Fixar o primeiro corte e resolver o resto recursivamente. **O problema da recursão ingênua:** Os mesmos subproblemas são resolvidos repetidamente $O(2^n)$. **Solução = Programação Dinâmica:**
| Abordagem | Ideia | Custo | |---|---|---| | Recursão ingênua | Resolve tudo do zero | $O(2^n)$ | | Memoização | Guarda o que já calculou | $O(n^2)$ | | Bottom-up | Constrói de baixo para cima | $O(n^2)$ | > Subproblemas se repetem? **Lembre-se deles.** > Essa é a essência da Programação Dinâmica.
